## Pillar 1: 🧠 Reasoning (The Decision Engine)

### What "Reasoning" Actually Means in an Agent

The LLM doesn't "think" in the human sense. It performs **contextual pattern matching** to produce the most probable next action. But with the right prompting, this looks remarkably like reasoning.

### The Reasoning Prompt Structure

Every agent call to the LLM has this structure:

```python
messages = [
    # 1. SYSTEM PROMPT: Who you are, what you can do, how to behave
    {
        "role": "system",
        "content": """You are a research assistant. You have access to these tools:
        - web_search(query): Search the internet
        - read_page(url): Read a webpage
        - write_file(path, content): Save content to a file
        
        RULES:
        - Always search before answering factual questions
        - Cite sources
        - If a tool fails, try a different approach
        - When done, provide a final text answer (no tool call)
        """
    },
    
    # 2. USER MESSAGE: The goal
    {"role": "user", "content": "Research the top 3 AI agent frameworks"},
    
    # 3. ASSISTANT MESSAGE: Previous reasoning + tool call
    {
        "role": "assistant",
        "content": "I'll research AI agent frameworks. Let me start with a search.",
        "tool_calls": [{"id": "call_1", "function": {"name": "web_search", "arguments": "{\"query\": \"best AI agent frameworks 2025\"}"}}]
    },
    
    # 4. TOOL RESULT: What happened
    {
        "role": "tool",
        "tool_call_id": "call_1",
        "content": "Results: 1. LangGraph 2. CrewAI 3. AutoGen..."
    },
    
    # Now the LLM reasons again: what to do NEXT?
]
```

### Reasoning Techniques (Prompt Engineering for Agents)

#### Technique 1: ReAct (Reason + Act)

The most common pattern. The LLM explicitly states its reasoning before acting:

```
Thought: I need to find AI agent frameworks. Let me search for recent comparisons.
Action: web_search("best AI agent frameworks 2025 comparison")
Observation: [search results]
Thought: I found 3 frameworks. Now I need details on each. Let me get LangGraph first.
Action: web_search("LangGraph features pros cons")
Observation: [results]
...
Thought: I have enough information to write a comprehensive comparison.
Action: [final answer, no tool call]
```

**Implementation:** You prompt the LLM to output in this format, then parse it:

```python
REACT_PROMPT = """Answer the question using this format:

Thought: [your reasoning about what to do next]
Action: [tool_name(arguments)]
Observation: [result from tool - I will provide this]
... (repeat Thought/Action/Observation as needed)
Thought: I now have enough information to answer.
Final Answer: [your complete answer]
"""
```

#### Technique 2: Chain-of-Thought (CoT)

Force the LLM to show its work before deciding:

```python
# Without CoT:
"Which tool should I use?" → LLM might pick wrong tool

# With CoT:
"Think step by step:
 1. What information do I need?
 2. Which tool provides that?
 3. What arguments does it need?
 4. Are there any risks?
 Then decide." → Much better tool selection
```

**Research finding:** Adding "Let's think step by step" to prompts improves reasoning accuracy by 20-40% on complex tasks (Wei et al., 2022).

#### Technique 3: Self-Reflection

After producing output, the agent critiques its own work:

```python
REFLECTION_PROMPT = """You just completed a task. Review your work:
1. Did I actually answer the user's question?
2. Are my claims supported by the tool results?
3. Did I miss anything important?
4. Is there a better approach I should try?

If improvements are needed, take another action. Otherwise, provide the final answer.
"""
```

#### Technique 4: Structured Decision Making

Force the LLM to output a structured decision:

```python
DECISION_PROMPT = """Before acting, output your decision as JSON:
{
    "reasoning": "Why I'm taking this action",
    "confidence": 0.0-1.0,
    "tool": "tool_name or null",
    "arguments": {...},
    "alternatives_considered": ["other options I rejected"],
    "risks": ["what could go wrong"]
}
"""
```

### Reasoning Quality Factors

| Factor | Impact | How to Improve |
|--------|--------|----------------|
| **Model choice** | GPT-4o >> GPT-4o-mini for complex reasoning | Use best model for planning, cheaper for execution |
| **Prompt clarity** | Vague prompts → wrong tool selection | Be explicit about when to use each tool |
| **Context quality** | Garbage in → garbage out | Summarize tool results before feeding back |
| **Temperature** | High temp → creative but unreliable | Use 0-0.2 for tool selection, 0.7 for final answers |
| **Examples** | Few-shot examples dramatically improve accuracy | Include 2-3 examples of correct tool usage |

### Failure Modes of Reasoning

| Failure | Example | Fix |
|---------|---------|-----|
| **Wrong tool** | Uses calculator for a search query | Better tool descriptions + examples |
| **Infinite loop** | Keeps searching same thing | Add iteration limit + "you've tried this before" context |
| **Premature stop** | Answers without searching | Prompt: "ALWAYS use tools for factual questions" |
| **Hallucinated tool** | Calls a tool that doesn't exist | Validate tool names before execution |
| **Wrong arguments** | `search(query="")` empty string | Add parameter validation + examples |

## Pillar 2: 🛠️ Tools (The Action Layer)

### What a Tool Actually Is (Technically)

A tool is a **function schema** that the LLM can request to execute. The LLM doesn't execute anything — it just outputs a JSON request. YOUR code executes it.

### The Tool Definition (OpenAI Format)

```python
tools = [
    {
        "type": "function",
        "function": {
            "name": "web_search",                    # Unique identifier
            "description": "Search the internet for current information. Use this for factual questions, recent events, or anything you're unsure about.",  # WHEN to use it
            "parameters": {                          # JSON Schema for arguments
                "type": "object",
                "properties": {
                    "query": {
                        "type": "string",
                        "description": "The search query. Be specific and concise."
                    },
                    "num_results": {
                        "type": "integer",
                        "description": "Number of results to return (1-10)",
                        "default": 5
                    }
                },
                "required": ["query"]                # Must-have parameters
            }
        }
    },
    {
        "type": "function",
        "function": {
            "name": "calculate",
            "description": "Perform mathematical calculations. Use for any math beyond simple arithmetic.",
            "parameters": {
                "type": "object",
                "properties": {
                    "expression": {
                        "type": "string",
                        "description": "Math expression to evaluate, e.g. '15 * 85 / 100'"
                    }
                },
                "required": ["expression"]
            }
        }
    }
]
```

### What the LLM Outputs (Tool Call)

When the LLM decides to use a tool, it returns:

```json
{
    "role": "assistant",
    "content": "Let me search for that information.",
    "tool_calls": [
        {
            "id": "call_abc123",
            "type": "function",
            "function": {
                "name": "web_search",
                "arguments": "{\"query\": \"AI agent frameworks 2025\", \"num_results\": 5}"
            }
        }
    ]
}
```

**Critical detail:** `arguments` is a **JSON string**, not a JSON object. You must parse it:

```python
import json

tool_call = response.choices[0].message.tool_calls[0]
function_name = tool_call.function.name
arguments = json.loads(tool_call.function.arguments)  # Parse the string!
```

### Tool Execution (Your Code)

```python
def execute_tool(function_name: str, arguments: dict) -> str:
    """Route tool calls to actual implementations."""
    
    if function_name == "web_search":
        # Call a real search API (SerpAPI, Tavily, Brave, etc.)
        results = search_api.query(arguments["query"])
        return format_results(results)
    
    elif function_name == "calculate":
        # Safe math evaluation
        try:
            result = eval(arguments["expression"], {"__builtins__": {}})
            return str(result)
        except Exception as e:
            return f"Error: {e}"
    
    else:
        return f"Error: Unknown tool '{function_name}'"
```

### Feeding Results Back

```python
# After executing the tool, add the result to messages:
messages.append({
    "role": "tool",
    "tool_call_id": "call_abc123",  # Must match the tool_call id!
    "content": "Results:\n1. LangGraph - ...\n2. CrewAI - ...\n3. AutoGen - ..."
})

# Then call the LLM again with the updated messages
response = client.chat.completions.create(
    model="gpt-4o",
    messages=messages,
    tools=tools
)
```

### Tool Design Principles

| Principle | Bad | Good |
|-----------|-----|------|
| **Naming** | `do_thing()` | `search_web()` |
| **Description** | "Searches stuff" | "Search the internet for current information. Use for facts, news, or verification." |
| **Parameters** | `input: string` | `query: string (the search terms)`, `num_results: int (1-10, default 5)` |
| **Return value** | Raw API response (5000 tokens) | Formatted summary (500 tokens) |
| **Error handling** | Crash | Return "Error: [description]" as string |
| **Side effects** | Hidden (sends email silently) | Explicit (requires confirmation) |

### Tool Categories

```
READ tools (safe, no side effects):
  - web_search, read_file, get_weather, query_database
  
WRITE tools (modify state, need caution):
  - write_file, send_email, create_calendar_event
  
EXECUTE tools (dangerous, need sandboxing):
  - run_code, execute_sql, shell_command
  
META tools (agent management):
  - ask_user, delegate_to_agent, save_memory
```

### How Many Tools?

| # Tools | LLM Performance | Use Case |
|---------|----------------|----------|
| 1-5 | Excellent (>95% accuracy) | Simple agents |
| 5-15 | Good (85-95%) | Most production agents |
| 15-30 | Degraded (70-85%) | Complex assistants |
| 30+ | Poor (<70%) | Use hierarchical routing |

**Solution for many tools:** Group them and use a "router" that selects a category first:

```python
# Instead of 50 tools, use 5 categories:
router_tools = [
    {"name": "research_tools", "description": "Search, read, analyze"},
    {"name": "communication_tools", "description": "Email, chat, notify"},
    {"name": "file_tools", "description": "Read, write, edit files"},
    {"name": "data_tools", "description": "Database, API, analytics"},
    {"name": "system_tools", "description": "Code execution, scheduling"},
]
# Then load specific tools based on selected category
```

## Pillar 3: 💾 Memory (The State Layer)

### The Core Problem

LLMs are **stateless**. Every API call is independent. The model doesn't remember your previous call. "Memory" means **you** manage what context to include in each call.

```python
# The LLM sees THIS and nothing else:
response = client.chat.completions.create(
    model="gpt-4o",
    messages=messages  # ← THIS is the "memory". That's it.
)
```

### Implementation: Working Memory

```python
class ConversationMemory:
    """Manages the message list that becomes the LLM's context."""
    
    def __init__(self, max_tokens: int = 100_000):
        self.messages: list[dict] = []
        self.max_tokens = max_tokens
        self.token_count = 0
    
    def add_system(self, content: str):
        self.messages.insert(0, {"role": "system", "content": content})
        self.token_count += len(content) // 4  # rough estimate
    
    def add_user(self, content: str):
        self.messages.append({"role": "user", "content": content})
        self.token_count += len(content) // 4
    
    def add_assistant(self, content: str, tool_calls: list = None):
        msg = {"role": "assistant", "content": content}
        if tool_calls:
            msg["tool_calls"] = tool_calls
        self.messages.append(msg)
        self.token_count += len(content) // 4
    
    def add_tool_result(self, tool_call_id: str, content: str):
        self.messages.append({
            "role": "tool",
            "tool_call_id": tool_call_id,
            "content": content
        })
        self.token_count += len(content) // 4
    
    def get_messages(self) -> list[dict]:
        """Return messages, trimming if over token limit."""
        if self.token_count > self.max_tokens:
            self._trim()
        return self.messages
    
    def _trim(self):
        """Remove oldest non-system messages to fit within limit."""
        # Keep system prompt (index 0) and recent messages
        # Summarize or drop middle messages
        while self.token_count > self.max_tokens and len(self.messages) > 3:
            removed = self.messages.pop(1)  # Remove oldest non-system
            self.token_count -= len(removed.get("content", "")) // 4
```

### Implementation: Long-Term Memory (Vector DB)

```python
# Using a simple in-memory vector store for illustration
import numpy as np
from openai import OpenAI

client = OpenAI()

class LongTermMemory:
    """Persistent memory using embeddings for retrieval."""
    
    def __init__(self):
        self.memories: list[dict] = []  # {text, embedding, metadata}
    
    def store(self, text: str, metadata: dict = None):
        """Store a memory with its embedding."""
        embedding = self._embed(text)
        self.memories.append({
            "text": text,
            "embedding": embedding,
            "metadata": metadata or {}
        })
    
    def retrieve(self, query: str, top_k: int = 3) -> list[str]:
        """Find most relevant memories for a query."""
        query_embedding = self._embed(query)
        
        # Cosine similarity search
        scored = []
        for mem in self.memories:
            similarity = np.dot(query_embedding, mem["embedding"]) / (
                np.linalg.norm(query_embedding) * np.linalg.norm(mem["embedding"])
            )
            scored.append((similarity, mem["text"]))
        
        scored.sort(reverse=True)
        return [text for _, text in scored[:top_k]]
    
    def _embed(self, text: str) -> list[float]:
        response = client.embeddings.create(
            model="text-embedding-3-small",
            input=text
        )
        return response.data[0].embedding
```

### Memory Strategies for Context Management

| Strategy | How It Works | When to Use |
|----------|-------------|-------------|
| **Full history** | Include all messages | Short conversations (<10 turns) |
| **Sliding window** | Keep last N messages | Long conversations, simple tasks |
| **Summarization** | Compress old messages into summary | Long conversations, complex tasks |
| **RAG** | Retrieve only relevant memories | Very long histories, knowledge bases |
| **Hierarchical** | Summary + recent details | Production agents |

### The Summarization Pattern

```python
def summarize_old_messages(messages: list[dict], keep_recent: int = 5) -> list[dict]:
    """Compress old messages into a summary, keep recent ones intact."""
    
    if len(messages) <= keep_recent + 1:  # +1 for system prompt
        return messages
    
    system = messages[0]
    old_messages = messages[1:-keep_recent]
    recent_messages = messages[-keep_recent:]
    
    # Use LLM to summarize
    summary_prompt = f"""Summarize this conversation history into 2-3 sentences.
    Focus on: what was accomplished, key decisions, important context.
    
    History:
    {format_messages(old_messages)}
    """
    
    summary = call_llm(summary_prompt)
    
    return [
        system,
        {"role": "user", "content": f"[Previous conversation summary: {summary}]"},
        *recent_messages
    ]
```

## Pillar 4: 🗺️ Planning (The Strategy Layer)

### What Planning Means for Agents

Planning = **decomposing a complex goal into executable steps** and **adapting the plan** as new information arrives.

### Planning Approaches (From Simple to Complex)

#### Approach 1: Implicit Planning (ReAct)

The LLM plans one step at a time. No explicit plan document.

```
User: "Research and compare the top 3 cloud providers"

Step 1: LLM thinks "I need to identify the top providers first"
        → Action: search("top cloud providers 2025")
        
Step 2: LLM thinks "Found AWS, Azure, GCP. Need pricing details."
        → Action: search("AWS vs Azure vs GCP pricing comparison")
        
Step 3: LLM thinks "I have pricing. Need feature comparison."
        → Action: search("AWS Azure GCP features comparison")
        
Step 4: LLM thinks "I have enough to write a comparison."
        → Final answer (no tool call)
```

**Pros:** Simple, adaptive, no upfront cost
**Cons:** Can lose track of goal, no overview, hard to debug

#### Approach 2: Explicit Planning (Plan-then-Execute)

Generate a full plan first, then execute step by step.

```python
PLANNING_PROMPT = """Given this goal, create a step-by-step plan.
Output as JSON: {"steps": [{"id": 1, "action": "...", "tool": "...", "expected_result": "..."}]}

Goal: {user_goal}
Available tools: {tool_names}
"""

# Step 1: Generate plan
plan = call_llm(PLANNING_PROMPT.format(user_goal=goal, tool_names=tools))
plan = json.loads(plan)

# Step 2: Execute each step
for step in plan["steps"]:
    result = execute_step(step)
    # Optionally: re-plan if result is unexpected
```

**Pros:** Clear overview, debuggable, user can review plan
**Cons:** Rigid, may be wrong from the start, doesn't adapt well

#### Approach 3: Adaptive Planning (Plan → Execute → Re-plan)

```python
def adaptive_agent(goal: str, max_replans: int = 3):
    plan = generate_plan(goal)
    
    for replan_count in range(max_replans):
        for step in plan["steps"]:
            result = execute_step(step)
            
            if result.is_unexpected:
                # Re-plan based on what we learned
                plan = replan(
                    original_goal=goal,
                    completed_steps=plan["steps"][:step_index],
                    new_information=result
                )
                break  # Restart execution with new plan
        
        if plan_is_complete(plan):
            break
    
    return synthesize_results(plan)
```

### Planning Failure Modes

| Failure | Example | Fix |
|---------|---------|-----|
| **Over-planning** | 20 steps for a simple question | Add "prefer fewer steps" to prompt |
| **Under-planning** | Tries to do everything in one search | Prompt: "break complex goals into sub-questions" |
| **Plan drift** | Forgets original goal after 5 steps | Include goal in every prompt |
| **Infinite planning** | Keeps re-planning, never executes | Limit replans to 2-3 |
| **Wrong decomposition** | Breaks goal into irrelevant sub-tasks | Use examples of good decomposition |

## How All 4 Pillars Interact (Complete Example)

```python
class SimpleAgent:
    """A complete agent showing all 4 pillars working together."""
    
    def __init__(self):
        self.client = OpenAI()
        self.tools = self._define_tools()          # PILLAR 2: Tools
        self.memory = ConversationMemory()          # PILLAR 3: Memory
        self.max_iterations = 10                    # PILLAR 4: Planning (safety)
    
    def run(self, goal: str) -> str:
        # Initialize memory with system prompt (PILLAR 1: Reasoning setup)
        self.memory.add_system(self._build_system_prompt())
        self.memory.add_user(goal)
        
        # THE AGENT LOOP (where all pillars interact)
        for iteration in range(self.max_iterations):
            
            # PILLAR 1: REASONING — LLM decides what to do
            response = self.client.chat.completions.create(
                model="gpt-4o",
                messages=self.memory.get_messages(),  # PILLAR 3: Memory provides context
                tools=self.tools,                      # PILLAR 2: Tools available
                temperature=0.1                        # Low temp for reliable decisions
            )
            
            message = response.choices[0].message
            
            # PILLAR 4: PLANNING — Did the LLM decide to act or finish?
            if message.tool_calls:
                # Agent wants to use a tool (continue the plan)
                self.memory.add_assistant(
                    message.content,
                    tool_calls=message.tool_calls
                )
                
                for tool_call in message.tool_calls:
                    # PILLAR 2: TOOLS — Execute the action
                    result = self._execute_tool(
                        tool_call.function.name,
                        json.loads(tool_call.function.arguments)
                    )
                    
                    # PILLAR 3: MEMORY — Store the result
                    self.memory.add_tool_result(tool_call.id, result)
            
            else:
                # Agent is done (plan complete)
                return message.content
        
        return "I wasn't able to complete this within the step limit."
    
    def _build_system_prompt(self) -> str:
        return """You are a helpful research assistant.
        
        APPROACH (PILLAR 4 - Planning):
        1. Understand the question
        2. Search for information
        3. Verify key facts
        4. Synthesize an answer
        
        RULES (PILLAR 1 - Reasoning):
        - Always search before answering factual questions
        - If a search fails, try different keywords
        - Cite your sources
        - Be concise but complete
        """
    
    def _define_tools(self) -> list:
        return [
            {
                "type": "function",
                "function": {
                    "name": "web_search",
                    "description": "Search the internet for information",
                    "parameters": {
                        "type": "object",
                        "properties": {
                            "query": {"type": "string", "description": "Search query"}
                        },
                        "required": ["query"]
                    }
                }
            }
        ]
    
    def _execute_tool(self, name: str, args: dict) -> str:
        if name == "web_search":
            return search_api(args["query"])  # Your search implementation
        return f"Error: Unknown tool {name}"
```

## The Pillars Maturity Model

As you build more sophisticated agents, each pillar evolves:

| Level | Reasoning | Tools | Memory | Planning |
|-------|-----------|-------|--------|----------|
| **Beginner** | Single prompt | 1-2 tools | Message list | Implicit (ReAct) |
| **Intermediate** | CoT + few-shot | 5-10 tools | Sliding window | Explicit plan |
| **Advanced** | Self-reflection | 10-20 tools + routing | Vector DB + summarization | Adaptive re-planning |
| **Production** | Ensemble + voting | 20+ tools + sandboxing | Hierarchical + persistent | Tree-of-thought + reflection |

**You'll build all 4 levels in this course.**
