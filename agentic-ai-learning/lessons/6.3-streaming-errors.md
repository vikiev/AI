## Part 1: Streaming (Don't Make Users Wait)

### The Problem

```python
# User clicks "Ask"... then NOTHING for 8 seconds... then full response appears
response = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Explain quantum computing"}]
)
print(response.choices[0].message.content)  # ← 8 seconds of blank screen!
```

### The Fix: `stream=True`

```python
from openai import OpenAI
from dotenv import load_dotenv

load_dotenv()
client = OpenAI()

stream = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Explain quantum computing simply"}],
    stream=True  # ← ONE parameter changes everything
)

for chunk in stream:
    if chunk.choices[0].delta.content:
        print(chunk.choices[0].delta.content, end="", flush=True)
# Output appears word-by-word, like ChatGPT! ✨
```

### How Streaming Works

```
Normal:    [──────── 8 seconds ────────] → "Full response here..."

Streaming: [0.5s] "Quantum" 
           [0.6s] " computing"
           [0.7s] " uses"
           [0.8s] " qubits..."
           → User sees text appearing in real-time!
```

### Streaming + Collecting (For Agent Loops)

When you need BOTH streaming display AND the full response:

```python
def stream_and_collect(messages, tools=None):
    """Stream to screen while collecting full response."""
    stream = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=messages,
        tools=tools,
        stream=True
    )
    
    full_content = ""
    
    for chunk in stream:
        delta = chunk.choices[0].delta
        if delta.content:
            print(delta.content, end="", flush=True)  # Show to user
            full_content += delta.content              # Save for later
    
    print()  # newline
    return full_content

# Use it
answer = stream_and_collect([
    {"role": "user", "content": "What is an AI agent?"}
])
# User sees it stream, AND you have `answer` for further processing
```

## Part 2: Error Handling (APIs WILL Fail)

### The Errors You'll Actually Hit

| Error | When | What to do |
|-------|------|------------|
| `RateLimitError` | Too many requests/minute | Wait + retry |
| `APIConnectionError` | Network hiccup | Retry |
| `BadRequestError` | Prompt too long | Trim context |
| `AuthenticationError` | Bad API key | Fix .env (don't retry!) |
| `Timeout` | Taking too long | Retry with shorter prompt |

### Production-Grade Wrapper

```python
import time
from openai import OpenAI, RateLimitError, APIConnectionError, BadRequestError

client = OpenAI(timeout=30.0)  # ← Never wait more than 30s

def safe_llm_call(messages, tools=None, max_retries=3):
    """LLM call that handles real-world failures."""
    
    for attempt in range(max_retries):
        try:
            response = client.chat.completions.create(
                model="gpt-4o-mini",
                messages=messages,
                tools=tools,
                max_tokens=2000  # ← Cap output! Prevents runaway costs
            )
            return response
            
        except RateLimitError:
            wait = 2 ** attempt  # 1s → 2s → 4s (exponential backoff)
            print(f"⚠️ Rate limited. Waiting {wait}s...")
            time.sleep(wait)
            
        except APIConnectionError:
            wait = 2 ** attempt
            print(f"⚠️ Connection issue. Retrying in {wait}s...")
            time.sleep(wait)
            
        except BadRequestError as e:
            print(f"❌ Bad request (probably too long): {e}")
            raise  # Don't retry — fix your input!
            
        except Exception as e:
            print(f"❌ Unexpected: {e}")
            raise
    
    raise Exception("Failed after max retries")
```

### Why Exponential Backoff?

```
Attempt 1: fail → wait 1s
Attempt 2: fail → wait 2s  
Attempt 3: fail → wait 4s

If everyone retries instantly → server stays overloaded
If everyone waits progressively → server recovers ✅
```

## Part 3: Cost Control (Don't Get a $500 Surprise)

### The Danger

```python
# Agent loop with no limits:
while True:  # ← INFINITE LOOP
    response = call_llm(messages)  # ← Each call costs money
    if response.tool_calls:
        messages.append(...)  # ← Context grows... costs grow...
        # Could run 100+ iterations = $$$
```

### The Fix: Budgets

```python
class AgentBudget:
    """Prevents runaway spending."""
    
    def __init__(self, max_tokens=50000, max_tool_calls=15):
        self.tokens_used = 0
        self.tool_calls = 0
        self.max_tokens = max_tokens
        self.max_tool_calls = max_tool_calls
    
    def track(self, response):
        """Call after every LLM response."""
        self.tokens_used += response.usage.total_tokens
        if self.tokens_used > self.max_tokens:
            raise Exception(f"🛑 Budget exceeded: {self.tokens_used} tokens!")
    
    def track_tool(self):
        """Call before every tool execution."""
        self.tool_calls += 1
        if self.tool_calls > self.max_tool_calls:
            raise Exception(f"🛑 Too many tool calls: {self.tool_calls}!")
    
    def report(self):
        # gpt-4o-mini: ~$0.15 per 1M input tokens
        cost = self.tokens_used * 0.00000015
        print(f"📊 Tokens: {self.tokens_used:,} | Tools: {self.tool_calls} | ~${cost:.4f}")

# Use in agent loop:
budget = AgentBudget(max_tokens=30000, max_tool_calls=10)

for i in range(10):  # ← ALSO limit iterations!
    response = safe_llm_call(messages, tools)
    budget.track(response)
    
    if not response.choices[0].message.tool_calls:
        break
    
    for tc in response.choices[0].message.tool_calls:
        budget.track_tool()
        # ... execute tool

budget.report()  # 📊 Tokens: 12,450 | Tools: 4 | ~$0.0019
```

## Part 4: Context Window Management

### The Problem

```python
# After 50 messages in a conversation:
messages = [system, user1, assistant1, user2, assistant2, ...]  # 100+ messages!
# → "context_length_exceeded" error 💥
```

### The Fix: Trim Old Messages

```python
def trim_context(messages, max_chars=80000):
    """Keep system prompt + recent messages. Drop old ones."""
    total = sum(len(m.get("content", "") or "") for m in messages)
    
    while total > max_chars and len(messages) > 3:
        # Remove second message (keep system at [0] and recent messages)
        removed = messages.pop(1)
        total -= len(removed.get("content", "") or "")
        print(f"🗑️ Trimmed old message ({len(messages)} remaining)")
    
    return messages

# Before every LLM call:
messages = trim_context(messages)
response = safe_llm_call(messages)
```

### Rule of Thumb

```
gpt-4o-mini context: 128,000 tokens
1 token ≈ 4 characters
128,000 tokens ≈ 512,000 characters

But you should trim at ~80,000 chars because:
- Output tokens also count
- Tool results add bulk
- Leave room for the response
```

## 🧪 TRY IT: Bulletproof Agent

Combine everything:

```python
"""
🛡️ Production Agent — streaming + retries + budget + logging
"""
import time, logging
from openai import OpenAI, RateLimitError, APIConnectionError
from dotenv import load_dotenv

load_dotenv()
client = OpenAI(timeout=30.0)
logger = logging.getLogger("agent")
logging.basicConfig(level=logging.INFO, format="%(asctime)s %(message)s")

def safe_call(messages, tools=None, stream=False):
    for attempt in range(3):
        try:
            return client.chat.completions.create(
                model="gpt-4o-mini",
                messages=messages,
                tools=tools,
                max_tokens=2000,
                stream=stream
            )
        except (RateLimitError, APIConnectionError):
            wait = 2 ** attempt
            logger.warning(f"Retry in {wait}s...")
            time.sleep(wait)
    raise Exception("Failed after retries")

def run_agent(user_input, tools=None, max_steps=10):
    messages = [
        {"role": "system", "content": "You are a helpful assistant."},
        {"role": "user", "content": user_input}
    ]
    total_tokens = 0
    
    for step in range(max_steps):
        response = safe_call(messages, tools)
        total_tokens += response.usage.total_tokens
        logger.info(f"Step {step+1}: {response.usage.total_tokens} tokens")
        
        msg = response.choices[0].message
        messages.append(msg)
        
        if not msg.tool_calls:
            logger.info(f"Total tokens: {total_tokens}")
            return msg.content
        
        # Execute tools...
        for tc in msg.tool_calls:
            logger.info(f"Tool: {tc.function.name}")
            # ... execute and append result
    
    return "Max steps reached."

print(run_agent("What is 25 * 4?"))
```

## Production Checklist

Before deploying ANY agent:

- [ ] `stream=True` for user-facing responses
- [ ] Retry with exponential backoff (3 attempts)
- [ ] `timeout=30.0` on client
- [ ] `max_tokens=2000` on every call
- [ ] Token budget with hard limit
- [ ] Max tool calls limit
- [ ] Max loop iterations (prevent infinite loops)
- [ ] Context trimming for long conversations
- [ ] Logging at every step
- [ ] Graceful error messages (not raw stack traces)

## ✅ Knowledge Check

1. What does `stream=True` do?
2. Why exponential backoff instead of instant retry?
3. What are THREE things you should limit to control costs?
4. Why trim context instead of sending everything?
5. What's the difference between `RateLimitError` and `BadRequestError` handling?

<details>
<summary>Answers</summary>

1. Returns tokens as they're generated (real-time display) instead of waiting for full response.
2. Instant retries from many clients keep the server overloaded. Spacing out lets it recover.
3. Max tokens per call, max tool calls, max loop iterations.
4. Context has a limit (128K tokens). Long conversations exceed it → error. Also costs more.
5. RateLimit = temporary, retry works. BadRequest = your fault (too long), retrying won't help.

</details>
