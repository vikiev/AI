# 📚 Lesson 6.1 — Structured Outputs: Real Data, Not Just Text

## 🎯 The Problem

LLMs return text. But your app needs **data**:

```python
# ❌ Without structured outputs — you parse text manually
response = "The weather is 32 degrees and sunny"
# Now you need regex to extract 32... painful!

# ✅ With structured outputs — you get real data
response = {"temperature": 32, "unit": "celsius", "condition": "sunny"}
# Just use response["temperature"] directly!
```

**Time:** ~25 minutes  
**Prerequisites:** Module 3 complete (function calling)

---

## Method 1: JSON Mode (Quick & Simple)

```python
from openai import OpenAI
from dotenv import load_dotenv
import json

load_dotenv()
client = OpenAI()

response = client.chat.completions.create(
    model="gpt-4o-mini",
    response_format={"type": "json_object"},  # ← Forces valid JSON
    messages=[
        {"role": "system", "content": "Return data as JSON with keys: name, age, city"},
        {"role": "user", "content": "Extract: John is 30 and lives in Mumbai"}
    ]
)

data = json.loads(response.choices[0].message.content)
print(data["name"])  # "John"
print(data["age"])   # 30
```

**⚠️ Limitation:** You get valid JSON, but NO guarantee about keys or types.

---

## Method 2: Pydantic (Production-Grade)

This is the **best** way. Guaranteed schema + types:

```python
from pydantic import BaseModel
from openai import OpenAI
from dotenv import load_dotenv

load_dotenv()
client = OpenAI()

# ─── DEFINE YOUR SCHEMA ─────────────────────────────────────
class WeatherReport(BaseModel):
    city: str
    temperature: float
    unit: str
    condition: str
    humidity_percent: int

# ─── GET STRUCTURED OUTPUT ──────────────────────────────────
response = client.beta.chat.completions.parse(
    model="gpt-4o-mini",
    messages=[
        {"role": "system", "content": "Extract weather information."},
        {"role": "user", "content": "It's 32 degrees and sunny in Mumbai, humidity around 75%"}
    ],
    response_format=WeatherReport  # ← Pydantic model!
)

weather = response.choices[0].message.parsed

# Now you have a REAL Python object:
print(weather.city)              # "Mumbai"
print(weather.temperature)       # 32.0 (float!)
print(weather.humidity_percent)  # 75 (int!)
print(type(weather.temperature)) # <class 'float'> ✅
```

### Why this is powerful:

| Feature | Benefit |
|---------|---------|
| Guaranteed schema | LLM MUST return exactly these fields |
| Type safety | `temperature` is always float, never "thirty-two" |
| Auto-validation | Pydantic checks constraints |
| IDE autocomplete | `weather.` shows all fields |

## Method 3: Enums for Constrained Choices

```python
from enum import Enum
from pydantic import BaseModel

class Sentiment(str, Enum):
    POSITIVE = "positive"
    NEGATIVE = "negative"
    NEUTRAL = "neutral"

class Review(BaseModel):
    text: str
    sentiment: Sentiment  # ← MUST be one of the 3 values
    confidence: float

response = client.beta.chat.completions.parse(
    model="gpt-4o-mini",
    messages=[
        {"role": "user", "content": "Analyze: 'The product is amazing but shipping was slow'"}
    ],
    response_format=Review
)

review = response.choices[0].message.parsed
print(review.sentiment)    # Sentiment.NEUTRAL
print(review.confidence)   # 0.7
```

The LLM **cannot** return "mixed" or "okay" — only your enum values!

## 🧪 TRY IT: Extract Book Data

```python
class Book(BaseModel):
    title: str
    author: str
    year: int
    genre: str

response = client.beta.chat.completions.parse(
    model="gpt-4o-mini",
    messages=[
        {"role": "user", "content": "Extract: '1984' by George Orwell, published 1949, dystopian fiction"}
    ],
    response_format=Book
)

book = response.choices[0].message.parsed
print(f"{book.title} ({book.year}) by {book.author}")
# → 1984 (1949) by George Orwell
```

## When to Use What

| Need | Use |
|------|-----|
| Quick JSON, don't care about schema | `response_format={"type": "json_object"}` |
| Guaranteed fields + types | `client.beta.chat.completions.parse()` + Pydantic |
| Constrained choices (yes/no, categories) | Pydantic + Enum |
| Tool parameters | Function calling (already structured!) |

## 🚨 Common Pitfalls

### 1. Forgetting "JSON" in prompt (JSON mode only)

```python
# ❌ Might fail — no mention of JSON
messages=[{"role": "user", "content": "Extract the name"}]

# ✅ Works — tells model to use JSON
messages=[
    {"role": "system", "content": "Return as JSON"},
    {"role": "user", "content": "Extract the name"}
]
```

### 2. Too-complex schemas

```python
# ❌ Deep nesting confuses the LLM
class Company(BaseModel):
    departments: list[Department]  # Department has teams, teams have members...

# ✅ Keep it flat
class Employee(BaseModel):
    name: str
    department: str
    team: str
```

### 3. Optional fields

```python
from typing import Optional

class Person(BaseModel):
    name: str
    age: Optional[int] = None  # LLM might not find this
    email: Optional[str] = None
```
